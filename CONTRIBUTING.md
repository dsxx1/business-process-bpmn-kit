# Как вносить изменения

1. Создайте ветку от `main`: `feature/<краткое-название>` или `fix/<краткое-название>`.
2. Меняйте один процесс или один аспект стандарта за раз.
3. Обновляйте одновременно человеческую карточку, BPMN и реестр переходов.
4. В `tools/bpmn` запустите `npm run verify:all`.
5. Проверьте `git diff --check` и отсутствие секретов.
6. Создайте Merge Request (на GitHub — Pull Request) и назначьте другого
   участника reviewer.

Автоматическая проверка `npm run verify:ci` запускается на каждый push и на
каждый запрос на слияние: в GitHub Actions — `.github/workflows/verify.yml`,
в GitLab CI — `.gitlab-ci.yml`. Зелёная проверка подтверждает только
техническую корректность и не является бизнес-приёмкой процесса.

Merge Request должен отдельно отвечать на три вопроса:

- что изменилось для человека;
- что изменилось в BPMN/XML;
- требуется ли новое бизнес-решение или изменение адаптера движка.
