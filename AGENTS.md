# Правила проекта

- Все названия, которые видит человек, писать полными русскими словами. Не показывать внутренние коды вместо смысла действия.
- Технические XML-идентификаторы должны быть стабильными, ASCII-совместимыми и смысловыми: `Task_CalculatePreliminaryPrice`, а не `Task_03`.
- Эталонные модели `as-is` и `to-be` не содержат расширений конкретного BPMN-движка и имеют `isExecutable=false`.
- Исполняемую модель хранить отдельным адаптером под конкретный движок. Не заменять ею нейтральный источник.
- Не объявлять бизнес-процесс утверждённым без решения уполномоченного владельца. Техническая валидация не является бизнес-утверждением.
- Не угадывать неизвестный следующий процесс. Оставлять связь в состоянии `unresolved` и формулировать вопрос владельцу.
- Между независимыми процессами использовать вызов процесса или обмен сообщением. Link Event допустим только внутри одной области процесса.
- Перед коммитом запускать `npm run verify:all` из `tools/bpmn` и `git diff --check`.
- Не коммитить `node_modules`, временные профили браузера, секреты, токены, `.env`, выгрузки БД и необработанные персональные данные.
- Работать в отдельной ветке и отправлять изменения через Merge Request. Не переписывать историю общей ветки.
