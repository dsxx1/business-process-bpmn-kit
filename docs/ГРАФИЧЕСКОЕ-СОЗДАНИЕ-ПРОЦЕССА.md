# Как нарисовать BPMN-процесс

Для обычной работы нужен один файл в корне проекта:

```text
ОТКРЫТЬ-BPMN-РЕДАКТОР.cmd
```

Дважды щёлкните его. Откроется графический редактор в браузере. Чёрное окно с
анкетой заполнять не нужно.

## Самый короткий путь

1. Нажмите **«Новая схема»**.
2. На холсте появится готовая основа:
   **получен запрос → уточнить данные → можно выполнить? → выполнить работу или
   завершить без результата**.
3. Дважды щёлкните подпись блока и напишите свой текст.
4. Перетаскивайте блоки мышью. Выберите блок и используйте появившуюся панель,
   чтобы добавить следующее действие, развилку или результат.
5. Нажмите **«Сохранить как…»** и выберите любое имя и любую папку.

После первого сохранения `Ctrl+S` записывает изменения в тот же файл. Если
браузер не поддерживает прямую запись, редактор скачает обновлённый `.bpmn` и
честно сообщит об этом.

## Открыть готовую схему

Нажмите **«Открыть BPMN»** и выберите файл `.bpmn`. Можно также перетащить файл
на окно редактора. Исходный файл не изменится, пока вы не нажмёте «Сохранить».

Формат стандартный BPMN 2.0. Тот же файл можно открыть в Camunda Desktop
Modeler, Bizagi и другом совместимом редакторе.

## Как читать обозначения

| Фигура | Что означает | Пример подписи |
|---|---|---|
| Тонкий круг | Начало | «Получена заявка» |
| Прямоугольник | Действие | «Проверить документы» |
| Ромб | Вопрос или условие | «Данных достаточно?» |
| Толстый круг | Результат | «Результат передан» |
| Дорожка | Роль | «Специалист по закупкам» |
| Стрелка | Очерёдность | «Да», «Нет», «Нужна проверка» |

Название файла и всего процесса может быть любым. Для самих шагов полезно писать
понятно: действие + результат. Это рекомендация для читаемости, а не запрет на
ваше название.

## Проверить схему

Нажмите **«Проверить»**. Для отдельного файла редактор проверит, что XML
открывается как BPMN и схема может быть снова сохранена. Для процесса проекта
добавятся проверки структуры пакета, связей, статусов и производных файлов.

Первая ошибка показывается сразу обычным русским текстом. Полный технический
отчёт можно раскрыть в разделе «Дополнительно».

## Перейти в следующий бизнес-процесс

Эта функция доступна у процесса проекта:

1. Выберите обычную задачу.
2. Нажмите **«Сделать вызовом другого процесса»**.
3. Выберите готовый процесс, будущий процесс или вариант «цель пока неизвестна».
4. Сохраните схему.

Редактор использует стандартный BPMN Call Activity и сам синхронизирует
`calledElement`. Готовую цель можно открыть в том же окне. Будущая цель получает
карточку-заглушку, которую позже можно заменить настоящим BPMN с тем же
постоянным идентификатором.

## Построить карту Archify

Archify — это не редактор, а удобная карта для чтения:

1. Откройте процесс проекта.
2. Выберите **«Дополнительно» → «Показать процессы проекта»** и откройте процесс.
3. Откройте вкладку **«Карта для человека»** и нажмите
   **«Построить карту Archify»**.

После изменения BPMN старая карта помечается как устаревшая. Нажмите
«Пересобрать карту» — вручную переносить блоки не нужно.

## Когда нужен процесс проекта

Обычного `.bpmn` достаточно, чтобы нарисовать схему или передать её
разработчику. Процесс проекта нужен, если требуется:

- хранить карточку, вопросы и основания;
- связывать несколько бизнес-процессов;
- строить и проверять Archify;
- регистрировать версии и фиксировать решение владельца;
- давать доступ ИИ-агенту через MCP.

Пакеты, карты и межпроцессные связи находятся в **«Дополнительно»** и не мешают
обычному рисованию. MCP запускается отдельной командой, а решение владельца
фиксируется отдельным сопровождающим действием.

## Что больше не требуется

- вводить «полное русское название» в терминале;
- придумывать `slug`, XML ID или имя папки до начала работы;
- устанавливать отдельную программу для рисования;
- использовать ИИ;
- редактировать XML руками.

Сам `bpmn-js` лежит в репозитории вместе с лицензией и контрольными суммами.
При первом запуске могут устанавливаться только служебные Node.js-зависимости
для локального сервера, проверок, Archify и MCP.
