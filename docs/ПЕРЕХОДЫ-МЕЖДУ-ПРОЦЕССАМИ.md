# Как связывать процессы

## Встроенный подпроцесс

Используйте, когда детализация принадлежит только текущему процессу и не имеет самостоятельного жизненного цикла. Пользователь раскрывает её внутри той же схемы.

## Вызываемый процесс — Call Activity

Используйте, когда отдельный повторно используемый процесс вызывается, возвращает результат, и родительский процесс после этого продолжается. Пример: согласование повышенной оценки.

## Независимая передача — message handoff

Используйте, когда текущий процесс завершил свою ответственность и передал данные следующему процессу. Родитель не ждёт возврата. Пример: после завершения сделки изделие и учётные данные уходят в складской процесс.

## Уведомление

Используйте, когда связанный контур получает информацию, но не становится владельцем основного маршрута. Пример: уведомление финансового мониторинга.

## Link Event

Link Event соединяет удалённые участки только внутри одной области BPMN-процесса. Его нельзя использовать как ссылку на другой самостоятельный процесс.

## Реестр

`registry/processes.json` связывает стабильный `process_id` с файлами модели и навигатора. Навигатор действует так:

1. если целевой процесс зарегистрирован, открывает его подробную схему;
2. если известна только карточка-кандидат, открывает карточку;
3. если цель неизвестна, честно показывает `unresolved`.

Автоматическое совпадение по похожему названию не считается подтверждённой связью.
