# Как добавить новый процесс

## 1. Сначала опишите смысл

До BPMN заполните карточку:

- зачем существует процесс;
- какое событие его запускает;
- какой результат означает завершение;
- кто участвует;
- какие документы и системы используются;
- где основной маршрут, исключения и переходы в другие процессы;
- какие факты подтверждены, а какие ещё требуют решения.

## 2. Создайте пакет из шаблона

Скопируйте `templates/process-package` в `processes/<короткое-название>` и замените:

- полное русское название;
- смысловой технический ID;
- роли и шаги;
- вопросы владельцу;
- ссылки на доказательства.

Не используйте номер процесса как основное название папки или схемы.

## 3. Сделайте карту для человека

На карте оставьте 5–9 крупных этапов. Сначала покажите успешный маршрут, затем отдельными ветвями — отказ, ошибку и передачу в другой процесс. Человек должен понять карту без легенды технических кодов.

## 4. Детализируйте в BPMN

Сохраните исходник в `bpmn/process.bpmn`. Для каждого крупного узла карты должна существовать понятная группа BPMN-элементов. Стабильную связь можно записать в `map/process-map.bindings.json`.

## 5. Опишите переходы

Каждый переход в другой процесс записывается в `process.meta.json`:

- от какого BPMN-элемента он начинается;
- это вызов с возвратом, передача, исключение или уведомление;
- какой процесс является целью;
- подтверждена цель или пока только кандидат.

Если цель неизвестна, используйте `unresolved`. Не выбирайте процесс по похожему названию автоматически.

Для вызова с возвратом используйте Call Activity: значение `calledElement` должно точно совпадать с `target_process_id` в метаданных. Для независимой передачи завершите текущий процесс сообщением и зарегистрируйте следующий процесс как отдельную цель.

## 6. Зарегистрируйте процесс

Добавьте запись в `registry/processes.json`. После этого навигатор другого процесса сможет открыть подробную BPMN-схему вместо запасной карточки.

## 7. Проверьте

```powershell
Set-Location tools\bpmn
npm ci
node validate-package.mjs ../../processes/<короткое-название>/bpmn --require-registry
npx bpmnlint --config ../../docs/.bpmnlintrc ../../processes/<короткое-название>/bpmn/process.bpmn
```

После регистрации `npm run verify:registry` автоматически найдёт и полностью проверит новый пакет. Отдельную команду в `package.json` добавляйте только тогда, когда процессу нужна собственная сборка производных файлов.

## 8. Проведите две проверки

- содержательную — владелец процесса подтверждает маршрут, роли и решения;
- техническую — разработчик или BPMN-аналитик проверяет XML, переносимость и интеграционный профиль.

Только после обеих проверок можно говорить, что процесс готов к использованию по назначению.
