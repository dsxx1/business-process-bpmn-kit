# Переходы между BPMN-процессами

## Что уже работает

Студия и локальный MCP используют один и тот же контракт перехода `call`: текущий процесс вызывает другой BPMN-процесс, ждёт его завершения и затем продолжает работу. На схеме это стандартный BPMN `Call Activity`, а не нарисованная вручную ссылка.

ИИ для этого не нужен. Человек может настроить переход в Студии; любой MCP-агент может сделать ту же операцию через готовые инструменты. Каноническим источником остаются два файла пакета:

- `process.bpmn` — форма и поведение схемы;
- `process.meta.json` → `process_links` — человекочитаемая связь и состояние цели.

Оба файла изменяются вместе или не изменяются вообще. Перед записью проверяются два SHA-256, поэтому правка из другого окна не затирается.

## Три понятных варианта цели

| Выбор человека | Что записывается | Что можно открыть |
| --- | --- | --- |
| Существующий процесс | Его постоянный `process_id`, статус связи `candidate` | Зарегистрированный BPMN-процесс в Студии |
| Будущий процесс | Зарезервированные slug и `process_id`, статус `candidate` | Текстовая карточка будущего процесса |
| Пока неизвестно | Без придуманного ID, статус `unresolved` | Ничего, пока цель не уточнена |

`candidate` означает «технически связано, но не утверждено владельцем». Студия и MCP никогда не меняют бизнес-статус на `canonical` и не принимают решение за человека.

Для будущего процесса Студия создаёт карточку в `related-processes/<slug>.md`. Если затем создать и зарегистрировать пакет с теми же slug и постоянным `process_id`, навигатор начнёт открывать готовый BPMN автоматически — исходный переход переделывать не нужно. Существующая карточка принимается только при точном совпадении её служебной метки, slug и `process_id`; чужой файл не будет молча привязан.

Название процесса может быть любым непустым однострочным текстом: русским,
английским, цифровым или внутренним. Подпись самого перехода на схеме должна
оставаться понятной человеку и формулироваться по-русски.

## Как пользоваться в Студии

1. Откройте исходный процесс на вкладке **«BPMN-схема»** и выберите обычную
   задачу или уже созданный блок вызова. Панель **«Связать с другим процессом»**
   откроется справа автоматически.
2. Если выбрана обычная задача, нажмите
   **«Сделать этот шаг вызовом другого процесса»**. Студия сохранит подпись и
   стрелки и заменит задачу стандартным `Call Activity`.
3. Выберите готовый, будущий или пока неизвестный процесс.
4. Напишите понятную русскую подпись: что именно будет сделано в другом
   процессе.
5. Нажмите **«Сохранить связь»**. Студия атомарно обновит BPMN и метаданные и
   покажет результат без файлового редактора.
6. На вкладке **«Карточка и вопросы»** используйте **«Открыть процесс»** для
   готовой цели или **«Открыть карточку будущего процесса»** для
   карточки-заготовки. Карточка открывается как безопасный текст, а не
   исполняемый HTML.

Чтобы удалить связь, выберите её `Call Activity` на схеме и нажмите
**«Удалить связь»** в той же панели. После подтверждения Студия сама удалит
метаданные и превратит блок обратно в обычную задачу; BPMN и метаданные
сохраняются вместе или не изменяются вообще.

Существующий `LINK-...` нельзя перенести на другой BPMN-блок. Удалите старую связь и создайте новую — так на исходном блоке не останется скрытого вызова.

## HTTP-контракт Студии

### Получить цели и текущие переходы

`GET /api/process/:slug/transition-targets`

Основная форма ответа:

```json
{
  "ok": true,
  "schema": "bpmn-studio-transition-targets/v1",
  "source": {
    "slug": "исходный-процесс",
    "process_id": "ИСХОДНЫЙ-ПРОЦЕСС",
    "title": "Любое название процесса",
    "bpmn_sha256": "...",
    "meta_sha256": "..."
  },
  "supported_relations": ["call"],
  "supported_target_kinds": ["registered", "reserved", "unknown"],
  "targets": { "registered": [], "reserved": [] },
  "transitions": [],
  "skipped": []
}
```

Каждый переход содержит исходные поля `process_links` и поля отображения:

- `target_resolution`: `registered_bpmn`, `fallback_card` или `unresolved`;
- `target_title`, `target_slug`;
- `open.kind`: `process`, `card` или `none`;
- `open.card_markdown`: содержимое карточки либо `null`.

`open.card_markdown` нужно показывать как текст/Markdown с безопасным рендерингом, но не вставлять в DOM как доверенный HTML.

### Создать или изменить

- создать: `POST /api/process/:slug/transitions`;
- изменить: `PUT /api/process/:slug/transitions/:linkId`.

```json
{
  "expected_bpmn_sha256": "64-символьный SHA-256",
  "expected_meta_sha256": "64-символьный SHA-256",
  "xml": "полный текущий BPMN XML",
  "source_element_id": "CallActivity_CheckDocuments",
  "relation": "call",
  "label": "Проверить документы в отдельном процессе и вернуться",
  "target": { "kind": "registered", "slug": "proverka-dokumentov" }
}
```

Вместо зарегистрированной цели допустимы:

```json
{ "kind": "reserved", "title": "Проверка документов вручную", "slug": "ruchnaya-proverka-dokumentov" }
```

или:

```json
{ "kind": "unknown" }
```

У `reserved` поле `slug` можно не передавать: Студия сформирует безопасное
техническое имя из названия. Для стабильных внешних ссылок лучше показать
предложенный slug человеку перед сохранением.

Успешный ответ содержит `transition`, свежий объект `process` с `xml`, `sha256`, `meta_sha256` и `transitions`, результат инспекции и русское пояснение `notice`. Создание возвращает HTTP 201, изменение — 200.

### Удалить

`DELETE /api/process/:slug/transitions/:linkId`

```json
{
  "expected_bpmn_sha256": "64-символьный SHA-256 открытой версии",
  "expected_meta_sha256": "64-символьный SHA-256 открытой версии метаданных",
  "xml": "полный BPMN XML, где бывший Call Activity уже стал Task или удалён"
}
```

Успешный ответ содержит `transition: null`, `removed_transition` и свежий `process`.

Типовые конфликты:

- `BPMN_CONFLICT` или `META_CONFLICT` — перечитать процесс и повторить осознанно;
- `CALL_ACTIVITY_STILL_PRESENT` — сначала заменить вызов обычной задачей либо удалить блок;
- `TRANSITION_SOURCE_CHANGE_FORBIDDEN` — нельзя переносить один `LINK` между блоками;
- `RESERVED_CARD_CONFLICT` — выбранный путь уже занят другой карточкой;
- `INVALID_TITLE` — название пустое, многострочное или не прошло ограничение длины.

## Те же операции через MCP

MCP использует то же ядро Студии, блокировку, проверку путей и атомарную запись:

- `bpmn_list_transition_targets` — получить цели, переходы и два актуальных SHA-256;
- `bpmn_set_process_transition` — создать или изменить связь; для изменения передать `link_id`;
- `bpmn_remove_process_transition` — удалить связь после замены `CallActivity` на `Task` или удаления блока.

Аргументы MCP повторяют HTTP-поля в `snake_case`. `bpmn_set_process_transition` и `bpmn_remove_process_transition` намеренно имеют `idempotentHint: false`: после неизвестного результата вызова сначала перечитайте переходы, не повторяйте мутацию вслепую.

## Граница текущей версии

Мастер безопасно поддерживает только вызов с возвратом (`Call Activity`). Асинхронная передача управления без возврата — другой BPMN-смысл: она требует согласованной пары Message End/Message Start, участников и `messageFlow`. Такой переход пока не создаётся этим мастером и не должен имитироваться через `Call Activity`.

Человекочитаемая карта и Archify остаются производными представлениями. Они помогают читать процесс, но не заменяют BPMN XML и не превращают черновик в утверждённый бизнес-процесс.
