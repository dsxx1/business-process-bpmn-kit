# Исследование: как дать человеку готовый BPMN-инструмент

Дата проверки: 20 августа 2026 года.

## Короткий вывод

Проекту не нужен собственный движок рисования схем. Нужна русская локальная
оболочка над готовым BPMN-редактором и уже созданными проверками проекта.

Выбранный вариант:

- канонический источник — переносимый файл BPMN 2.0;
- графическое редактирование — встроенный `bpmn-js`;
- один локальный вход — `ОТКРЫТЬ-BPMN-РЕДАКТОР.cmd`;
- простая карта для руководителя — производное представление Archify;
- Camunda Desktop Modeler, Bizagi и другие редакторы остаются дополнительными;
- ИИ не требуется для создания, изменения, проверки и передачи процесса;
- реальное бизнес-утверждение подтверждается защищённым Merge Request, а не
  локальной кнопкой.

## Что проверено

### BPMN как нейтральный формат

[OMG BPMN 2.0.2](https://www.omg.org/spec/BPMN/2.0.2/) публикует формальную
спецификацию и XSD. Поэтому `process.bpmn`, а не внутренний JSON редактора,
остаётся машинным источником истины.

### bpmn-js

[Официальный walkthrough bpmn-js](https://bpmn.io/toolkit/bpmn-js/walkthrough/)
подтверждает, что библиотека:

- показывает и редактирует BPMN 2.0 в браузере;
- читает BPMN XML и экспортирует его обратно;
- может работать без серверного backend;
- расширяется собственными правилами, переводами и панелями;
- поставляется готовой браузерной сборкой.

[Основной репозиторий bpmn-js](https://github.com/bpmn-io/bpmn-js) на дату
исследования имеет свыше 9 тысяч звёзд, десятки релизов и активную поддержку.
В комплекте закреплена версия `18.25.1`, актуальная на 20 августа 2026 года.
Обновление с `18.16.1` проверено на импорте, редактировании, повторном сохранении,
детерминированном SVG/PNG-рендере и обязательном знаке bpmn.io.
Это существенно более зрелая основа, чем отдельные небольшие BPMN-редакторы и
MCP-генераторы. Экосистема уже содержит готовые
[примеры встраивания](https://github.com/bpmn-io/bpmn-js-examples),
[панель свойств](https://github.com/bpmn-io/bpmn-js-properties-panel),
[проверку через bpmnlint](https://github.com/bpmn-io/bpmn-js-bpmnlint) и
[симуляцию токенов](https://github.com/bpmn-io/bpmn-js-token-simulation).

Версия проекта закреплена в `package-lock.json`. Лицензия разрешает встраивание,
но требует сохранять видимый знак bpmn.io; Студия его не удаляет и не перекрывает.

Это не разработка ещё одного редактора: Студия использует зрелый графический
modeler и добавляет только русское сопровождение, файловые операции и проверки.

Панель технических свойств и симулятор токенов тоже изучены, но не включены
в первый экран. Панель перегружает новичка полями конкретного движка, а симуляция
показывает маршрут токена, но не доказывает работу форм, интеграций и прав доступа.
Оба расширения остаются совместимыми кандидатами для режима «для технического аналитика».

### Camunda Desktop Modeler

[Camunda Desktop Modeler](https://docs.camunda.io/docs/components/modeler/desktop-modeler/install-the-modeler/)
остаётся хорошим расширенным редактором: он локальный, зрелый и открывает `.bpmn`
как обычный файл. Его недостаток для первого знакомства — отдельная установка и
технический интерфейс. Поэтому он остаётся необязательным, а не главным входом.

### Flowable и Bizagi

[Flowable Design](https://documentation.flowable.com/latest/user/design/bpmn-editor/index.html)
имеет удобный drag-and-drop редактор, проверку и публикацию, но тесно связан с
продуктом и его исполняемой моделью.

[Bizagi Modeler](https://help.bizagi.com/platform/en/desktop-application.htm)
удобен для совместного документирования и умеет обмениваться BPMN 2.0.
[Документация экспорта Bizagi](https://help.bizagi.com/platform/en/exporting_to_bpmn.htm)
предупреждает, что расширенные атрибуты не входят в обычный BPMN-экспорт. Поэтому
импорт из Bizagi нужно принимать через проверяемую рабочую копию.

### Archify

[Archify](https://github.com/tt-a1i/archify) принимает типизированный JSON и
создаёт автономную интерактивную HTML-карту. Это сильное представление для
обсуждения процесса, но не BPMN-редактор и не формат обмена с BPMN-движком.

В текущем проекте уже есть хорошая Archify-карта скупки, однако до этой работы
точная русская сборка не входила в репозиторий, а шаблон нового процесса не умел
воспроизводимо строить такую карту. Поэтому Archify оформляется отдельным
закреплённым адаптером:

```text
process.bpmn
      │
      ├── подробная BPMN-схема для аналитика и разработчика
      │
      └── workflow JSON → Archify → карта для человека
```

Ручная карта аналитика имеет приоритет. Автоматическая карта честно называется
черновиком: программа не должна притворяться, что без смыслового решения умеет
идеально объединить десятки BPMN-элементов в семь бизнес-этапов.

### Готовые MCP-решения для BPMN

Проверены существующие GitHub-проекты
[BPMN-MCP](https://github.com/dattmavis/BPMN-MCP),
[mcp-bpmn](https://github.com/oisee/mcp-bpmn),
[bpmn-inspector-mcp](https://github.com/Djaler/bpmn-inspector-mcp) и
[StarUML Controller BPMN MCP](https://github.com/pontasan/staruml-controller-bpmn-mcp).
Они полезны как прототипы, но каждый закрывает только часть задачи: генерацию
диаграммы в памяти, просмотр и раскладку либо управление отдельно установленным
StarUML. Ни один не работает с нашим каноническим пакетом, реестром связанных
процессов, ожидаемым SHA-256, русскими проверками и границей бизнес-утверждения.

[draw.io MCP](https://github.com/lgazo/drawio-mcp-server) зрелее как универсальный
редактор схем, но его собственный XML не является каноническим BPMN 2.0 и потому
не подходит на роль источника для BPMN-движка.

Поэтому для агентов не заимствуется ещё один редактор. Используется официальный
[TypeScript SDK MCP](https://github.com/modelcontextprotocol/typescript-sdk) и
тонкий локальный адаптер над тем же Core, которым пользуется Студия. Он читает и
сохраняет обычный `process.bpmn`, умеет запускать те же проверки и Archify, но
намеренно не предоставляет агенту команду «утвердить от имени владельца».

Итог выбора готовых компонентов:

| Задача | Готовая основа | Что добавляет этот проект |
|---|---|---|
| Рисование BPMN | `bpmn-js` | русская оболочка, безопасное сохранение, пакет процесса |
| Проверка схемы | `bpmnlint` и `bpmn-moddle` | правила каноничности и человекочитаемости |
| Карта для чтения | Archify | связь с BPMN, русская обработка, воспроизводимая сборка |
| Доступ агентов | официальный MCP SDK | ограниченные инструменты над тем же Core |

## Сравнение трёх вариантов

| Вариант | Как работает | Плюсы | Ограничения |
|---|---|---|---|
| «Консьерж» | Одна кнопка ведёт по состояниям, схема открывается во внешней Camunda | Самый простой экран | Camunda и Node надо отдельно ставить |
| «Платформа адаптеров» | Студия объединяет Camunda, Bizagi, Archify и движки через плагины | Максимальная расширяемость | Слишком большой первый релиз |
| «Одно окно» | Локальная Студия в браузере со встроенным bpmn-js | Сразу работает, один интерфейс, BPMN остаётся переносимым | Нужно поддерживать небольшой локальный server/UI |

Выбран третий вариант с двумя идеями из остальных: одна рекомендуемая следующая
кнопка для новичка и версионируемые адаптеры для будущего расширения.

## Что принципиально не делаем

- не заменяем BPMN собственным JSON;
- не смешиваем нейтральную модель с Camunda/Flowable-specific настройками;
- не считаем импорт в движок доказательством работоспособности автоматизации;
- не угадываем неизвестный следующий процесс;
- не скрываем открытые вопросы;
- не выдаём локальный ввод роли за проверку личности владельца;
- не делаем ИИ обязательной частью Core.

## Итоговая продуктовая формула

```text
Один запуск
  → готовый стартовый процесс
  → графическое редактирование мышью
  → русские проверки и исправления
  → понятная карта Archify одним действием
  → техническая публикация черновика
  → решение владельца и защищённое GitLab-согласование
  → нейтральный пакет разработчику
```
