# Стандарт оформления бизнес-процесса

## Один процесс — несколько представлений

Одна перегруженная схема неудобна всем. Поэтому процесс хранится четырьмя согласованными слоями.

| Слой | Для кого | Что отвечает |
|---|---|---|
| Карта процесса | Руководитель и сотрудник | Что происходит от начала до результата |
| Карточка процесса | Аналитик и владелец | Где границы, роли, правила, исключения и вопросы |
| Нейтральный BPMN | Аналитик и разработчик | Точная логика событий, задач, развилок и связей |
| Адаптер движка | Разработчик и эксплуатация | Как процесс реально исполняется в выбранной платформе |

## Правила человеческого слоя

- Название процесса описывает результат или предмет работы полностью.
- Действие называется глаголом и объектом: «Рассчитать предварительную цену».
- Развилка формулируется вопросом, а исходящие стрелки — ответами.
- На основной карте показывается прямой успешный маршрут слева направо.
- Исключения отделяются визуально и не ломают чтение основного маршрута.
- Роли пишутся понятными должностями, а не названиями таблиц, классов или подразделений без расшифровки.
- Технический идентификатор не показывается вместо человеческого названия.

## Правила BPMN

- Один старт должен иметь понятное бизнес-событие.
- Каждый значимый исход имеет отдельное конечное событие.
- Exclusive Gateway либо разделяет маршрут, либо объединяет его, но не делает оба действия одновременно.
- Все задачи и развилки подписаны.
- Пулы и дорожки показывают ответственность, а message flow — взаимодействие между независимыми участниками.
- Подробность, которая живёт только внутри текущего процесса, оформляется встроенным подпроцессом.
- Повторно используемый процесс с возвратом оформляется Call Activity.
- Независимая передача в следующий процесс оформляется сообщением и отдельным завершением текущего процесса.

## Имена технических элементов

Технические ID остаются невидимыми для обычного читателя, но должны помогать разработчику:

```text
Process_GoldBuying
Task_CalculatePreliminaryPrice
Gateway_TermsAccepted
EndEvent_DealCompleted
```

Запрещённый стиль:

```text
BP_08
Task_03
OP_03
Gateway_7
```

## Статусы

| Статус | Значение |
|---|---|
| `draft` | Схема собирается |
| `review-ready` | Технически проверена и готова к содержательному разбору |
| `rework` | Требует исправления после проверки |
| `approved` | Есть формальное решение владельца |

Техническая проверка никогда автоматически не переводит процесс в `approved`.
