# Готовая стартовая модель бизнес-процесса

Это не пустая папка. Внутри уже есть нейтральная BPMN 2.0-модель с началом, уточнением входных данных, развилкой, рабочим действием, успешным и неуспешным исходами. Её можно сразу открыть в графическом BPMN-редакторе и переделать под реальную работу.

Обычный пользователь не должен копировать этот каталог или вручную заменять
`PROCESS-TEMPLATE`. Откройте `ОТКРЫТЬ-BPMN-РЕДАКТОР.cmd`, затем выберите
**«Дополнительно» → «Показать процессы проекта»**, затем нажмите
**«Добавить процесс в проект»**. Название может быть любым;
короткое имя папки и безопасные технические идентификаторы Студия предложит
сама. Созданный `bpmn/process.bpmn` сразу откроется во встроенной рисовалке.

Технический специалист может создать пакет командой:

```powershell
cd tools\bpmn
node create-process-package.mjs --title "Любое название" --slug example
```

## Что лежит в готовом пакете

1. `process-card.md` — смысл, границы, роли, маршрут и вопросы.
2. `map/process-map.md` — простая переносимая карта для человека.
3. `bpmn/process.bpmn` — каноническая нейтральная BPMN-схема.
4. `bpmn/process.meta.json` — версия, статус и переходы.
5. `bpmn/questions.json` — вопросы владельцу.
6. `bpmn/decisions.json` — только фактически принятые решения.
7. `evidence/README.md` — основания и границы доказанности.

Ручное копирование остаётся только запасным способом для технического
специалиста. В этом случае нужно самостоятельно заменить все шаблонные значения,
обновить хеши и проверить пакет. Для повседневной работы используйте Студию.

Дальнейший порядок одинаков для всех процессов: заполнить пакет и проверить его, технически зарегистрировать черновик, отдельно зафиксировать решение владельца, а после каждой правки зарегистрированной версии запускать обновление. Изменённая после решения владельца версия автоматически возвращается на повторную проверку, а прежнее решение остаётся в истории. Регистрация сама по себе не означает бизнес-утверждение. Локальная запись решения должна быть подтверждена уполномоченным владельцем через защищённое согласование Merge Request в GitLab, потому что мастер не аутентифицирует человека за компьютером.
